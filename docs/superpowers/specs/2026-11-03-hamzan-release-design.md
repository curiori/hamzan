## ねらいと成功の姿

ハムざんを子どもに試してもらったところ、大好評でした。いまは Expo Go で、PC の開発サーバーが動いている間だけ遊べます。これを、iPhone と iPad の App Store で公開するアプリにします。

子どもは、家では iPad、出先ではスマホで遊びます。どちらで開いても、前回の続きから始まってほしいので、記録を iCloud で同期します。

成功の姿は次のとおりです。

* 家の iPad と出先のスマホのどちらで開いても、レベル、★、たね、グッズ、おへやが前回の続きになっている
* PC がなくても、毎日遊べる
* App Store で公開され、ダウンロードして使える
* いま Expo Go で遊んでいる記録を、本番版に引き継げる

元の設計（`2026-10-29-hamzan-ios-design.md`）は Expo Go での実機確認までを目標にし、App Store への公開、iPad 用のレイアウト、クラウド同期、TestFlight での配布を対象外にしていました。この設計は、その続きです。学習、おへや、ショップの仕様は元の設計のままです。

## 前提として決めたこと

だれが決めたかを、それぞれに書きます。

1. 記録の同期は iCloud で行う（持ち主の判断）。同期するのは、同じ Apple アカウントでサインインした端末どうし
2. 家の iPad と出先のスマホは、同じ Apple アカウントでサインインしている。そのアカウントは、ファミリー共有の 13 歳未満の子ども用のアカウント（持ち主の答え）
3. App Store には、持ち主が個人で登録して公開する（持ち主の答え）。App Store の販売者名には本名が出る。価格は無料（推測）
4. ビルドと App Store への提出は、Expo の EAS（クラウド）で行う。Mac は使わない（私の判断）
5. 段階を 4 つに分け、①家族の端末への配布、②iCloud 同期、③iPad の画面を整える、④公開の準備と審査、の順に進める。段階ごとに実装計画を書く（私の判断）
6. App Store ではキッズカテゴリ（9〜11 歳）で公開する（私の判断。外部へ情報を送らない今の作りと合い、保護者が安心して選べる）
7. いまの Expo Go の記録は、本番版に引き継ぐ（推測）。この記録に、テスト用の機能は使っていない（持ち主の答え）
8. 公開する国は日本だけにする（私の判断。日本語の中学受験向けのアプリで、EU の販売者情報の公開や、米国の州ごとの年齢確認の決まりに合わせる作業を避ける。日本で求められることは④で確かめる）
9. ①の配布から、iPad でも全画面で使えるようにする（私の判断。お子さんは家では iPad で遊び、今の Expo Go でも全画面なので、見え方を下げない。画面をきれいに整えるのは③）
10. 開発ビルドは、本番とは別のアプリ ID と iCloud の入れ物を使う（私の判断。2 台での同期の確かめや最初からの確かめを、お子さんの本当の記録にふれずに行うため）

## 目標と対象外

### 目標

* iPhone と iPad 向けに、App Store で公開する
* 同じ Apple アカウントの端末どうしで、iCloud を通して記録を同期する
* iPad では縦横どちらでも、画面分割やウィンドウの大きさ変更でも崩れずに遊べる
* Expo Go の記録を、書き出しと読み込みで本番版へ移せる
* 公開の前に、EAS の内部配布で家族の端末に配って使う

### 対象外

* Android と Web 版の公開
* アカウント登録、ログイン、自前のサーバー
* 保護者が別の Apple アカウントの端末から、子どもの記録を見る機能
* 2 台で食い違った記録の自動の合体（どちらかを使い、もう片方は戻せる形で残す。②を参照）
* 課金（たねは練習でだけもらえる）、広告、分析ツール、外部のクラッシュ収集
* EAS Update（審査を通さない更新）。最初の公開では使わない
* 折りたたみの iPhone（iPhone Duo）向けの専用の見た目。画面の大きさの変化に対応することで動くが、専用の作り込みはしない

### やってはいけないこと

動いたとしても、次の状態になったら失敗とみなします。

* 同期のせいで記録が消える、または古い記録で上書きされて、子どもががんばった分がなくなる
* iCloud が使えないと遊べない（遊ぶのは常に端末の中の記録で、同期はその写しを届ける役）
* 子どもの名前や記録を、開発者や第三者が受け取る
* 練習の途中で、記録が別の端末のものに入れ替わる
* 元の設計の「やってはいけないこと」（たねをあおる仕組み、休んだ子を責める仕組み、学習ルールの変更）を破る

## 制約

* Expo SDK 58（React Native 0.88）で作る。②で開発ビルドに移ってからは、App Store 版の Expo Go の SDK に合わせる必要はなくなる。SDK は Expo の通常の更新に合わせて上げる
* 使う部品は、Expo の公式モジュールと、Expo の設定プラグインで組み込める既製のモジュールだけにする。Mac がないので、Swift や Objective-C のコードを自分では書かない。ネイティブの組み立ては EAS Build がクラウドで行う
* `src/domain` と `curriculum.json` は変えない。golden テストを含むドメインのテストは通ったままにする
* 記録の正は端末の中（AsyncStorage のキー `hamzan-ios-v1`、persist の version 2）。iCloud にはその写しを置く。元の設計の制約 C-1「記録は端末の中だけ」は、「端末の中と、本人の iCloud（同じ Apple アカウントの端末だけが読める）」に改める。開発者のもとへは何も送らない
* キッズカテゴリの決まり（App Review Guidelines 1.3 と 5.1.4）を守る。第三者へ情報を送らない。外へのリンクや購入の前に、保護者の確認を置く
* iPadOS 27 では、アプリは画面の大きさの変更を断れない（`UIRequiresFullScreen` が効かなくなった。Apple の TN3192）
* App Store への提出には、iPhone と iPad 13 インチのスクリーンショットと、プライバシーポリシーの URL が要る
* 費用は、Apple Developer Program が年 99 ドル（日本では App から登録すると 12,800 円）。EAS は無料枠（iOS のビルドは月 15 回まで）で始める。iCloud の容量は利用者の iCloud を使うので、開発側の費用はない
* この PC の npm の取得先は、新しい版が出てから届くまで数日遅れる（`EXPO_OFFLINE=1 bunx expo install --fix` で、入っている expo に同梱の版にそろえる）

## 全体の構成

### 記録の置き場所

| 置き場所                 | 中身                                   | 役割                            |
|----------------------|--------------------------------------|-------------------------------|
| 端末の中（AsyncStorage）   | PIN、プロフィール、選んでいる子、テスト用の設定           | 遊ぶときに読み書きする正                  |
| 利用者の iCloud（アプリ用の入れ物） | 家族全体のファイル 1 つと、子どもごとのファイル           | 同じ Apple アカウントの端末へ届ける写し        |
| 書き出したファイル（JSON）      | 端末の中の記録全体（テスト用の設定は除く）              | Expo Go からの引っ越しと、手動のバックアップ     |

1 人ぶんの記録は、練習を続けると 1〜2 MB になりうる（`facts` が最大 4000 件、`sets` が最大 600 件）。iCloud のキー・バリュー保存（全体で 1 MB、1024 キーまで）では足りないので、iCloud Drive のアプリ用の入れ物にファイルとして置く。

### 開発の進め方の変化

* ①までは、今と同じく Expo Go と web 表示で確かめる
* ②で iCloud のモジュールを入れると、Expo Go では同期が動かない。ここから、開発ビルド（EAS で作る、開発用の自分のアプリ）を iPhone と iPad に入れて確かめる
* web 表示と Expo Go では、同期の部分は何もしないで動くようにする（私の判断。画面の確認を手軽に続けるため。じゃまになったらやめてよい）
* 自動テスト（bun）、型チェック、lint、ドメインのテストは今までどおり

## ① 家族の端末に本番版を入れる

ねらいは、PC のサーバーなしで、お子さんが毎日遊べるようにすることです。

### 作業

* SDK 58 のブランチ（`upgrade/sdk-58`）を main に取り込む
* EAS の設定を作る。`eas.json` に、開発ビルド用（development）と本番用（production）の 2 つの設定を置く。ビルド番号は EAS が自動で上げる
* アプリの ID（bundle identifier）を決める（私の案は `com.mahori.hamzan`。iCloud の入れ物の ID もこれをもとにする。どちらも①で最初のビルドを作る前に確定し、そのあとは変えない）
* 開発ビルドは、別のアプリ ID（私の案は `com.mahori.hamzan.dev`）にして、本番版と同じ端末に並べて入れられるようにする
* iPad でも使えるようにする（`ios.supportsTablet` を有効にする）。①では今の画面のままで、今の Expo Go と同じく全画面で動けばよい（iPadOS 27 のウィンドウの大きさ変更で、大きく崩れないことは確かめる）
* 本番ビルドでは、テスト用の機能を出さない。保護者の画面の「テスト用」と、`dev` の各スイッチ（日付ずらし、すべて解放など）が対象。今は `app.json` の `extra.enableTestTools` で切り替えているので、ビルドの種類で値が変わるようにする（`app.config` でビルドの種類を読む）
* 記録の引っ越し（下を参照）
* 家族の端末には、EAS の内部配布（ad hoc）で配る。お子さんの Apple アカウントは 13 歳未満の子ども用なので、TestFlight は使えない（Apple の TestFlight の規約）
  * お子さんの iPhone と iPad を EAS に登録する（端末の UDID。EAS のリンクから設定用のプロファイルを入れる。入れられないときは UDID を調べて手で登録する）
  * ビルドをリンクから入れ、アプリを開くと出る案内に従って、端末で「デベロッパモード」をオンにする（設定の「プライバシーとセキュリティ」。再起動とパスコードが要る。Mac は要らない）
  * 内部配布のビルドに 90 日の期限はない。署名の証明書の期限（1 年）までは使える

### 記録の引っ越し（書き出しと読み込み）

* 保護者の画面の「データ」に、「記録を書き出す」と「記録を読み込む」を足す
* 書き出しは、端末の中の記録全体（PIN、すべてのプロフィール、選んでいる子）を 1 つの JSON ファイルにする。ファイルには、アプリ名、保存の形の版（今は 2）、書き出した日時を入れる。共有シートで、AirDrop やファイル App に渡す
* 読み込みは、ファイルを選び、中身を確かめてから（アプリ名、版、形）、今の記録と置き換える。置き換える前に、確認の窓で「今の記録は消えます」と伝える。古い版のファイルは、今の移行（`src/state/migrate.ts`）で新しい形にする
* テスト用の設定（`dev`）は書き出さない。読み込んだあとは既定値にする（Expo Go で「すべて解放」などを試していても、本番版に持ち込まない）
* 使う部品は expo-file-system、expo-sharing、expo-document-picker。どれも Expo Go に入っているので、この機能は Expo Go 版でも動く。今の Expo Go の記録を書き出して、本番版で読み込める
* 今は iPad と iPhone の Expo Go に、別々の記録がある。引き継ぐのはどちらか 1 つで、保護者が選ぶ（合体はしない）
* ②ができるまでは、本番版の iPad と iPhone も別々の記録になる。同じファイルを両方で読み込めば、同じところから始められる

### 完了の条件

* お子さんの iPhone と iPad に本番版（内部配布）が入り、PC のサーバーなしで遊べる
* iPad では全画面で遊べる
* Expo Go から書き出した記録を読み込み、続きから遊べる
* 本番ビルドに、テスト用の機能が出ていない
* 実機チェックリスト A〜D（元の設計）を本番版で通す

## ② iCloud で同期する

### しくみ

* iCloud Drive の、このアプリ用の入れ物にファイルを置く。ファイル App には見せない
* 置くファイルは、家族全体のファイル 1 つ（PIN、プロフィールの一覧、消したプロフィールの印）と、子どもごとのファイル（`Profile` 1 人ぶん）
* 「選んでいる子」（`activeId`）とテスト用の設定（`dev`）は、端末ごとのままにして同期しない
* どのファイルにも、変更の番号（1 ずつ増える）、最後に変えた端末の印、変えた日時を書く。端末は、最後に iCloud とそろえたときの番号を覚えておく

### 送ると受け取るとき

* 送る：記録が変わったら、数秒待ってまとめて書く。アプリが裏に回るときにも書く
* 受け取る：アプリを開いたとき、前に戻ってきたとき、iCloud から変更の知らせが来たとき

### どちらを使うかの決まり（ファイルごと）

* 端末だけが変わっていたら、iCloud に送る
* iCloud だけが変わっていたら、端末の記録を iCloud のものに入れ替える。ただし練習の途中（出題画面と結果の画面）では入れ替えず、ちずやおへやに戻ったときに入れ替える
* 両方とも変わっていたら（つながらないまま 2 台で遊んだ）、最後にそろえたときから練習したセットが多いほうを使う。もう片方は「同期で使わなかった記録」として端末に残し、保護者の画面から戻せるようにする
* 消したプロフィールは、もう片方の端末から戻ってこない（家族全体のファイルに、消した印を残す）

### 初めての端末と、iCloud が使えないとき

* 初めて開いた端末で、端末の中が空で iCloud に記録があれば、最初の設定（PIN、子どもの登録、診断）をせずに、その記録を使う。iCloud からの読み込みを少し待ち（「iCloud から記録を読み込んでいます」と出す）、時間がかかりすぎたら最初の設定に進む
* 端末の中と iCloud の両方に別の記録があったら（①の本番版を 2 台で使っていた場合など）、保護者にどちらを使うかを聞く。使わなかったほうは、上と同じく戻せる形で残す
* iCloud にサインインしていない、iCloud Drive が切ってある、容量がいっぱい、のときは、端末の中だけで遊べる
* 保護者の画面に、同期の状態（iCloud と同期しているか、最後にそろえた時刻、使えない理由）を出す

### 部品

* iCloud Drive を使う Expo 対応のライブラリを使う。第一候補は react-native-cloud-storage（iCloud に対応し、Expo の設定プラグインがあり、今も更新されている）
* 本格的に使う前に、SDK 58 の開発ビルドで、読み書き、変更の知らせ、2 台の間の同期を試す（スパイク）。合わなければ、CloudKit を使うモジュールに切り替える
* iCloud の権限（iCloud コンテナ）は、設定プラグインと EAS のクレデンシャル管理で設定する。開発ビルドは本番とは別の iCloud コンテナを使う
* 子ども用のアカウントでも iCloud Drive を使える。スパイクでは、お子さんの端末で iCloud Drive がオンになっていて、このアプリの入れ物に読み書きできることも確かめる

### テスト

* どちらを使うかの決まり、初めての端末の扱い、ファイルの形は、react-native を読まない純粋な TS にして、bun でテストする
* iCloud との読み書きは、開発ビルドか内部配布の本番版で、同じ Apple アカウントの 2 台を使って確かめる

### 完了の条件

* 同じ Apple アカウントの iPhone と iPad で、片方で練習すると、もう片方を開いたときに続きになっている
* 機内モードで遊んだあとも、つながったときに追いつく
* つながらないまま 2 台で遊んだときは、片方を使い、もう片方を保護者の画面から戻せる
* iCloud が使えない端末でも、ふつうに遊べる

## ③ iPad の画面を整える

* ①で iPad でも全画面で使えるようにしてあるので、③では iPad の画面をきれいに整える。iPad はどの向きでも、画面分割やウィンドウの大きさ変更でも使える。iPhone は今までどおり縦向き
* 画面の幅は、iPhone SE（375×667pt）から iPad 13 インチ（1032×1376pt）の縦横までを考える。細い窓や低い窓では、スクロールしてよい
* 方針（私の案）は次のとおり。細かい見た目は、③に入る前に、持ち主が Expo Go で iPad を試した感想を聞いて決める
  * ちず、ショップ、保護者の画面は、内容の幅に上限を設けて中央に置く
  * 出題画面は、横長の窓では問題とテンキーを左右に並べ、縦長の窓では今の並びにする
  * おへやは、部屋の絵を窓に合わせて大きくする（縦横比は保つ）
* 文字の大きさの設定（大きな文字）と VoiceOver への対応は、iPad でも保つ
* App Store 用の iPad 13 インチと iPhone のスクリーンショットは、web 表示をその大きさ（iPad 13 インチは 2064×2752 ピクセル）で撮って作る（私の判断。Mac とシミュレーターがないため）。iPhone と iPad の実機の見た目と食い違わないことを確かめる

### 完了の条件

* iPad の縦と横、画面分割、ウィンドウの大きさ変更で、どの画面も崩れずに遊べる
* iPhone での見た目と動きが変わっていない（実機チェックリスト A〜D）

## ④ 公開の準備と審査

### 持ち主の手続き

* Apple Developer Program に個人で登録する（①の最初のビルドより前に必要。登録には数日かかることがある）。App Store の販売者名に本名が出る
* お子さんの iPhone と iPad を EAS に登録し、デベロッパモードをオンにする（①。手順は私が用意する）
* App Store Connect でアプリを作る（④。手順は私が用意する）
* 審査への提出と公開のボタンを押す

### 開発側で用意するもの

* アプリの名前は「ハムざん」。使えないときは、副題を足すなどして決める
* 配信する国は日本だけ、価格は無料にする
* カテゴリは「教育」、キッズカテゴリの 9〜11 歳
* 年齢区分の質問への答え
* App のプライバシーは「データの収集なし」（iCloud のデータは利用者本人のもので、開発者は受け取らない）
* 輸出規制の申告（独自の暗号化は使っていないので、`ITSAppUsesNonExemptEncryption` を false にする）
* プライバシーポリシーとサポートのページ（日本語）。アプリのコードとは別の小さな公開リポジトリに置き、GitHub Pages で公開する（私の判断。アプリのコードは公開しない）。問い合わせ先には、このアプリ用に作るメールアドレスを載せる（私の判断。個人のメールアドレスを公開しないため）
* App Store の説明文、キーワード、スクリーンショット（iPhone と iPad 13 インチ）
* 審査員へのメモ（保護者の画面は最初に設定する PIN で開くこと、同期には iCloud を使うこと）
* キッズカテゴリの点検（外へのリンクがないか、あるなら保護者の確認の後ろか。第三者へ何も送っていないか）

### 完了の条件

* 実機チェックリスト A〜D と、新しいチェックリスト E を、本番ビルドで通す
* `eas build --profile production` で作り、`eas submit` で提出し、審査を通って公開される

## テストと確認

### 自動テスト

* 書き出しと読み込み：ファイルの形、確かめ（違うアプリのファイル、壊れたファイル、新しすぎる版を断る）、古い版の移行、テスト用の設定を持ち込まないこと
* 同期の決まり：どちらを使うか、練習中は入れ替えないこと、消したプロフィールが戻らないこと、初めての端末
* ビルドの種類によるテスト用の機能の切り替え

### 実機チェックリスト E（本番化）

* 本番版（内部配布）が、PC のサーバーなしで開いて遊べる
* Expo Go から書き出した記録を、本番版で読み込める
* iPad で練習すると、iPhone を開いたときに続きになっている（逆も）
* 機内モードで遊んでから戻すと、もう片方の端末に届く
* iCloud をオフにした端末でも遊べ、保護者の画面に同期できない理由が出る
* iPad の縦横、画面分割、ウィンドウの大きさ変更で崩れない
* 本番ビルドに「テスト用」が出ていない

## リスクと対策

* iCloud の同期は即時ではない（数秒から数分）。出先で開いた直後は、古い記録のことがある。開いたときに取りに行き、届いたら入れ替える（練習中は入れ替えない）
* ライブラリが SDK 58 で動かない。②の最初にスパイクで確かめ、だめなら CloudKit のモジュールに替える
* Mac がないので、ネイティブの不具合を手元で調べにくい。ネイティブの部分は既製のモジュールだけにする
* 内部配布のビルドは、署名の証明書が切れると（1 年）開けなくなる。公開までが長引いたら、切れる前に新しいビルドを入れる
* お子さんの端末で、スクリーンタイムなどの制限のために、設定用のプロファイルやデベロッパモードを入れられないことがある（未確認）。①の最初に確かめ、入れられなければ保護者が一時的に許可する。それでもだめなら④を先に進め、①の内容で App Store に公開してから、②と③を更新で届ける
* キッズカテゴリの審査で落ちる。④の点検で事前に確かめる

## 実装するときに決めること

* ファイル名、ファイルの中の項目名、変更の番号の持ち方
* 「数秒待ってまとめて書く」の秒数、iCloud からの読み込みを待つ時間
* iPad の各画面の幅の上限と、左右に並べる境目の幅
* 書き出したファイルの名前（日付と子どもの名前を入れるなど）
* 説明文とスクリーンショットの中身
