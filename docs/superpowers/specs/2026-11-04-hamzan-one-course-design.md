## ねらい

ご要望は2つです。

* 「塾の単元と普通のコースを分けないでほしい」
* 「アプリのコンテンツを配布後に更新・追加しても大丈夫なようにして」

前の作業（[塾の単元の設計](2026-11-04-hamzan-juku-units-design.md)）では、ステージ6〜9（28レベル）を、保護者が「塾の単元」として開く別の道にしました。これをやめ、89レベルを1本のコースに並べ直します。子どもは1つのちずを、同じ決まり（前提の★2で開く、ヒント→メモ→スピード、★、マスター、復習、ステージチェック、診断）で進みます。

あわせて、配布したあとにコースを変えても、子どもの記録がこわれないようにします。レベルを足す、並べ替える、名前（ID）を変える、外す、のどれをしても、アプリの更新を入れた端末で、進み具合、★、マスター、復習、ごほうびがそのまま残るようにします。

成功の姿は次のとおりです。

* ちずは1つで、ステージ0〜9の10ステージ、89レベルが1本に並ぶ。保護者の画面に「塾の単元」はない
* いま端末にある記録は、この更新のあとも1つも失われない。今の位置より前に入った新しいレベルは、各レベル5問のチェックで始める位置を決め、ヒントから全部やり直させない
* 次からのコンテンツの変更は、`src/course/course.json` と各仕様（`juku.json`）を直すだけで済み、記録の移行のコードを書かなくてよい。まちがった変更（IDを消す、使い回すなど）はテストが止める

## 決めたこと

ご要望にない部分は、次のように決めました（私の判断）。

1. 並び順は「技のつながり（前提）を先に、塾（四谷大塚 4年下）の時期を次に」で決め、新しい3つのステージを、ステージ4（3けたと大きな数）のすぐあと、受験の技の前に入れる。見積もりはコースの最後に置く（理由は「並び順」）
2. 単位の換算のステージの中は「長さ・重さ → 面積 → 体積・かさ → 時間 → 速さの換算 → 道のり・時間・速さ → ミックス」に並べ替える。長さ・面積・体積は「1辺の比」で、時間と速さは「60でくり上がる」でつながるため
3. 新しいレベルも、前提の★2で開く（今のレベルと同じ決まり）。保護者が開く仕組み、塾の回の名前と時期（第11回 角柱と円柱 など）はアプリから外す。App Store で配る教材に、1つの塾の1年の予定を入れないため
4. レベルとステージは、変わらない ID で記録する。画面に出す番号（ステージ5、レベル5-2 など）は、コースの中の位置から毎回つくり、ID から読み取らない
5. ステージ6〜9の28レベルの ID を、位置を表さない名前（`frac-reduce` など）に変える。まだ配布していないので、いま変えるのがいちばん安い。前の作業の記録が端末にあっても、名前の付け替え表で移す
6. ステージの ID は数のまま変えない（0〜9）。番号の表示は位置からつくるので、ID 5 の受験の技は「ステージ8」と出る。ステージの ID は使い回さない
7. 子どもの位置より前に新しいレベルが入ったら、そのレベルを「チェック待ち」にし、きょうの れんしゅうの最初のメインで、1日1ステージずつ各レベル5問のチェックをする（診断のミニチェックと同じ決まり）。位置よりあとに入ったレベルは、ふつうに進んで出会う
8. 診断は、10ステージ全部を、コースの並び順で確かめる
9. 保存データの形を version 3 に上げる。version 2（前の作業の記録を含む）から移す
10. 記録の合わせ込み（下の「記録の合わせ込み」）は、読み込むたびに必ず行う。同じ記録に何回行っても結果は同じにする
11. ごほうび（おへやのグッズ）は、コースから外したレベルの★2やマスターも数える。コンテンツの変更で、子どもがもらったものが消えないようにする
12. 2026-11-03 のリリース設計の課金（有料のステージ）はまだ作っていない。新しいステージを有料の側に入れるかは、リリースの作業で決める（引き継ぎ）
13. 合わせ込みは、アプリの知らない ID の記録を消さない。新しい版のアプリが書いた記録（EAS Update を戻したとき、古い版を開いたとき、のちの iCloud の同期）を古い版が読んでも、何も失わず、新しい版がもう一度読めば元どおりになる。画面と予定は、コースにある ID だけを使い、知らない ID は読み飛ばす
14. 並べ替えのあとの「前の位置」は、プロフィールが最後に見たコースの並びで決める。出会ったレベル（`course.seen`）を、そのときのコースの順に保存しておき、その順で最初の★2のないレベルを前の位置とする。その位置より前に来た、練習していない★2のないレベル（新しいレベルと、前へ動いたレベル）をチェック待ちにする

## 目標と対象外

### 目標

* 89レベルを1本の並びにし、ちず、きょうの れんしゅう、診断、ステージチェック、保護者の画面を、その並びで動かす
* コースの定義（`course.json`）と、変わらない ID、位置からつくる番号
* 保存データの移行（version 2 → 3）と、読み込むたびの合わせ込み
* 子どもの位置より前に入った新しいレベルのチェック
* コンテンツを変えるときの手順（AGENTS.md）と、まちがった変更を止めるテスト

### 対象外

* 出題、ヒント、判定、目標タイムの中身（前の作業のまま。前提の3か所だけ変える）
* サーバーからコンテンツを配ること。コンテンツはアプリの中（JS）にあり、App Store の更新か、のちの EAS Update で届く
* 課金（リリースの作業で行う）
* 書き出し・読み込み（リリースの作業で行う。そのとき、読み込んだ記録にも移行と合わせ込みを通す）

### やってはいけないこと

動いたとしても、次の状態になったら失敗とみなします。

* 更新を入れた端末で、★、マスター、復習の予定、ごほうび、たね、買ったものが1つでも消える
* 画面の番号を ID から読み取る（並びを変えたとき、番号がずれる）
* 合わせ込みが例外を出し、記録が読めなくなる（読めないときは、今の決まりどおり何も書き込まない）
* golden を含むドメインのテストが崩れる、またはステージ0〜5の出題や判定が変わる

## 制約

* `src/domain` と `curriculum.json` は変えない（AGENTS.md の決まり）。コースの並び、診断、きょうの れんしゅうは `src/course` で組み直し、ステージ0〜5だけのコースでは今のドメインと同じ結果になることをテストで確かめる
* テストが読むモジュールは react-native と Expo を import しない
* 記録は端末の中だけ（AsyncStorage のキー `hamzan-ios-v1`）

## 並び順

| 番号 | ステージ ID | ステージ | レベル数 | 主な前提 |
|---|---|---|---|---|
| 0 | 0 | 数の感覚 | 5 | なし |
| 1 | 1 | たし算・ひき算の基本（20まで） | 10 | 0 |
| 2 | 2 | 九九とわり算の基本 | 9 | 1 |
| 3 | 3 | 2桁の暗算 | 14 | 0〜2 |
| 4 | 4 | 3桁と大きな数 | 12 | 3 |
| 5 | 6 | 小数と分数 | 8 | 九九、あまり、2桁×1桁、2桁÷1桁 |
| 6 | 8 | 円周率の計算 | 7 | 3桁×1桁、位取り、約分 |
| 7 | 7 | 単位の換算 | 7 | 0の多いかけ算・わり算、分数と小数 |
| 8 | 5 | 受験の技 | 11 | 3、4 |
| 9 | 9 | 見積もり | 6 | 0の多い計算、小数のかけ算、速さ、体積 |

理由は次のとおりです。

* ステージ0〜4は、学校の小1〜小4の計算で、ほかのすべての土台になる。並びは変えない
* 小数と分数は、円周率（3.14、60/360）、単位（0.25時間）、見積もり（小数の大きさ）の土台なので、新しい3つの最初に置く。塾でも 4年下 第1回
* 円周率を単位より前に置く。塾の 4年下 では円（第3・9・11回）が速さ（第13回）より先に来る
* 新しい3つ（4年下の塾の単元の知識）を、受験の技（計算を短くする技）より前に置く。今の塾の単元に間に合うことを優先し、学年の目安（ステージ4 は小4、新しい3つと受験の技は小4〜小5）の順にもそろう
* 見積もりは、すべての単元の答えを確かめる力なので最後に置く

前提は次の3か所だけ変えます。受験の技がうしろに移り、新しいステージより前で練習できなくなるためです。

| レベル | 前の前提 | 新しい前提 | 理由 |
|---|---|---|---|
| 約分 | 2-7、5-10 | 2-7、3-12 | 両方をわれる数は、九九の逆と2桁÷1桁で探せる |
| 3.14の段 | 2-5、3-10 | 2-5、4-8 | 314×7 は3桁×1桁そのもの |
| よく出る2けた×3.14 | 3.14と位取り、5-4 | 3.14と位取り、3-10 | ×25 の「314÷4」はヒントで教える |

### 画面の番号

* ステージの番号は、コースの中のステージの位置（0から）
* レベルの番号は「ステージの番号-ステージの中の位置（1から）」
* 文の中のレベルの参照（ミックスの例「3-2〜3-13の問題」、ミスの直し方「0-4、3-8、4-7を短く復習」）は、画面に出すときに今の番号へ置きかえる。`curriculum.json` の文はレベルの ID の形で書かれているので、ID に当たる部分だけを置きかえる。`juku.json` の文は `{frac-reduce}` の形で ID を書く
* 子ども向けのレベルの名前に、ステージの番号を入れない（「ステージ3 ミックス」は「2けた ミックス」にする）

## コースの定義（course.json）

`src/course/course.json` を、コースの形の正にします。レベルとステージの中身（出題、モード、目標タイム、前提、ステージチェック）は、今までどおり `curriculum.json` と `juku.json` が正です。

* `version`：コースの版。コースの形を変えたら1つ上げる（今回は2。前の作業までを1とする）
* `stages`：ステージの並び。`{ "id": 0 }` の形。`levels` を書いたステージは、その並びを使う（書かなければ仕様のステージの並び）。あとでステージをまたいでレベルを動かすときに使う
* `renamedLevels`：前の ID から今の ID への付け替え表。付け替えの先は、今のコースのレベル
* `retiredLevels`、`retiredStages`：外したレベルとステージの ID。二度と使わない
* `levelIdsEverUsed`、`stageIdsEverUsed`：これまでにどれかの版で使ったすべての ID（付け替え前の ID と外した ID を含む）。足すだけで、消さない

テストで次を確かめます（`validateCourse()`）。

* 2つの仕様のすべてのレベルが、コースにちょうど1回出る。外したレベルはコースに出ない
* 前提はコースの中で前にある。ステージチェックのレベルはそのステージのレベル
* 今のレベルとステージの ID は、すべて「使ったことのある ID」にある（新しい ID を足し忘れると止まる）
* 「使ったことのある ID」は、どれも今のコースにあるか、付け替えの先が今のコースにあるか、外したものである（ID を消したり、付け替えを書き忘れたりすると止まる）
* 外した ID と付け替えの前の ID を、今のレベルに使っていない
* すべてのレベルとステージに、子ども向けの名前がある

## 記録の合わせ込み

`src/state/reconcile.ts` の `reconcileProfile(profile, course)` を、記録を読み込むたびに（persist の `merge`）、移行のあとにも、すべてのプロフィールへ通します。純粋な関数で、何回通しても結果は同じです。記録を消すことはしません。

1. 付け替え：`renamedLevels` で、進み具合、復習、事実の記録、ミスの記録、セットの記録、きょうの予定の復習の区切り、診断の記録、チェック待ち、出会ったレベルの ID を、今の ID に移す。同じレベルの進み具合が前の ID と今の ID の両方にあれば、進んでいる方（マスター、★2、練習ずみの順）を残す。復習の予定は今の ID の方を残す
2. コースにない ID（外したレベル、新しい版のアプリが足したレベル）：進み具合、ステージチェック、復習、事実、ミス、セット、チェック待ちの記録を、そのまま残す。ごほうびの数には入れる。画面と予定は読み飛ばす（下の「記録を読む側の決まり」）
3. 診断の途中：
   * 今いるステージがコースにないときは、コースの順で、学年の最初のステージから数えて最初のまだ合格していないステージのチェックに移る
   * 今いるステージより前に、新しいレベルを含み、まだ確かめていないステージが入ったら、そのステージのチェックに戻る（合格したステージはそのまま。1つ前のステージに下りる途中の記録 `pendingFrontier` は消す）
   * ミニチェックの位置がステージのレベルの数をこえたら、そのステージのチェックからやり直す
4. 前の位置：出会ったレベル（`course.seen`、最後に見たコースの順）のうち、今のコースにあり、★2がなく、チェック待ちでない最初のレベル。その今のコースでの位置を「前の位置」とする（なければコースの終わり）
5. チェック待ちに足す：診断が終わっているとき、前の位置より前にある、練習しておらず★2のないコースのレベル（新しいレベルと、前へ動いたレベル）
6. 片づけ：チェック待ちは、コースにあって★2のないものをコースの順に、そのあとにコースにないものを元の順に、重なりなく残す。★2をとったものは外す
7. 出会ったレベルを「今のコースのすべてのレベル（コースの順）、そのあとに、前からあってコースにない ID（元の順）」にする。`course.version` は、今の版と記録の版の大きい方にする

新しく作ったプロフィールは、はじめからコースのすべてのレベルに出会っていることにします。

### 記録を読む側の決まり

* きょうの予定、すすむ先、★3をめざす先、ステージチェック、チャレンジ、ウォームアップ、復習は、コースにあるレベルとステージだけを使う。復習は、コースにあるレベルの予定だけから、その日の数（`maxLevelsPerDay`）を選ぶ
* 保存されたきょうの予定に、知らない区切りや、コースにないステージのチェック、コースにないレベルの復習があれば、その区切りは「出す問題がない」として飛ばす
* ウォームアップに出す前の日のミスは、コースにあるレベルで、問題を作り直せるものだけにする（作り直せない問題は飛ばす）
* 保護者の画面は、コースにあるレベルだけを、番号つきで出す。ミスの種類は知っている種類だけを数える
* 診断を終えたとき（`skipPlacementTo` を含む）は、コースのレベルの進み具合を書き直し、コースにないレベルの進み具合と復習はそのまま残す

## あたらしいレベルのチェック

* きょうの れんしゅうは、チェック待ちがあると「ウォームアップ → あたらしい レベルの チェック → メイン1つ → 復習」になる。メイン1つは、ステージチェックがあればそれ、なければ「すすむ」（すすむ先がなければ★3をめざす）。1日のメインは2つのまま
* チェックの区切りは、チェック待ちの最初のレベルのステージを、その日の1ステージにする。そのステージのチェック待ちのレベルを、コースの順に5問ずつ（スピード、診断のミニチェックと同じ）出す
* ミスなし、かつ1問あたり T★2 以内なら合格：★2（その日の日付、スピードモード）にし、チェック待ちから外し、同じステージの次のチェック待ちへ進む。ステージに残りがなければ、区切りを終える
* つまずいたら、そのレベルから始める。まだ練習していないレベルは、ミスがあればはじめのモード（ヒントなど）、遅いだけならスピードにする。そのレベルと、同じステージの残りのチェック待ちを外し、区切りを終える（残りは、ふつうに進んで出会う）
* 途中でやめたセットは、何も変えない。区切りも終わらない
* チェックで出た★2は、ごほうびの数に入れない（診断と同じ。`rewardBaseline` に足す）。たねは正解の数だけ（診断と同じ）
* 「すすむ」の先は、チェック待ちのレベルを飛ばす。ちずでは、チェック待ちのレベルに「あたらしい」の印を出す
* 保護者の画面では、チェック待ちのレベルを「チェック待ち」と出し、進み具合の上に「アプリの更新で加わったレベルが N こあります。きょうの れんしゅうで、1日1ステージずつ、各レベル5問でたしかめます。」と出す

## 1日の練習と進み方

`src/course` に、ドメインの `progression.ts` と `session.ts` と同じ決まりを、コースの並びで組み直します。

* 開く：前提がすべて★2以上
* すすむ先（frontier）：コースの順で最初の、開いていて★2のない、チェック待ちでないレベル。同じ種類のスピードのセットで★2がとれないまま決まった回数を超えたら、前提のうちコースの順で最初のマスターしていないレベルへ戻る
* ★3をめざす先（pending）：★2でマスターしていないレベル。ステージチェックで落ちたレベルを先に、★2の日が古い順、次にコースの順
* ステージチェック：コースの順で最初の、すべてのレベルが★2以上で、まだチェックしていないステージ
* ウォームアップ：きょうの練習のステージの、全部の問題を数えあげられるレベル（新しいステージを含む）
* ステージ0〜5だけのコースでは、frontier、pending、ステージチェック、きょうの予定、区切りの解決が、ドメインの関数と同じになることを、ランダムな記録でテストする

## 診断

`src/course/placement.ts` に、ドメインの `placement.ts` と同じ決まりを、コースの並びで組み直します。

* 学年の最初のステージ（`startStageByGrade`、ステージ ID）からステージチェック。合格したら、コースの順で次の、まだ合格していないステージへ
* 落ちたら、そのステージの最初のレベルから各レベル5問のミニチェック。最初のレベルでつまずいたら、コースの順で1つ前のステージのチェックへ
* 終わったら、つまずいたレベルより前（コースの順）のレベルを★2にし、T★3 以内で合格したステージのレベルはマスターにして復習へ
* 保存している診断の途中の記録（ステージ ID と、確かめたステージ ID）は、そのまま読める
* ステージ0〜5だけのコースでは、ドメインの関数と同じ結果になることをテストする

## 保存データの移行（version 3）

version 2 から 3 へ移すとき、次を行います。そのあとで合わせ込みを通します。

* `juku`（開いた単元とチェック待ちの単元）を消す
* `course` を足す。出会ったレベルは「ステージ0〜5の61レベル（その順）と、そのあとに進み具合のあるほかの ID（前の作業のステージ6〜9の順）」。チェック待ちは空。版は1
* きょうの予定の「塾の単元」の区切りを、同じ種類（すすむ、または★3をめざす）のメインの区切りに変える
* セットの記録の種類 `juku_check` を `check` に変える

保存データの形（persist の version）が新しすぎる記録は、今の決まりどおり読み込みを失敗にし、何も書き込みません。形が同じで、コースの版だけが新しい記録は、そのまま読み込み、知らない ID を読み飛ばして使います（「記録の合わせ込み」の2と7）。

## 画面

* ちず：10ステージを並びの順に「ステージ5 しょうすうと ぶんすう」のように出す。レベルは位置の番号。チェック待ちのレベルに「あたらしい」。鍵の案内は前提の★2だけ
* レベルのシート：「レベル 5-2」、鍵の案内は前提の名前。例の文の番号は今の番号に置きかえる
* きょうの れんしゅう：「あたらしい レベルの チェック」の区切り。ステージチェックは「ステージチェック（ステージ8）」のように番号で出す
* 出題の画面：チェックのセットの小見出しは「あたらしい レベルの チェック」
* 結果：合格は「ごうかく！」と「つぎの レベルへ」（ステージの最後なら「チェック おわり！ つぎは ★3を めざそう」）。つまずいたら「「やくぶん」の ヒントから はじめよう」
* 診断：「ステージ5「しょうすうと ぶんすう」の チェック」「レベル 5-2」
* 保護者の画面：「塾の単元」のタブを消す。ダッシュボードは10ステージを並びの順に、番号つきで出す。苦手な事実と推移のレベルは番号で出す。ミスの直し方の補足（小数点の位置と単位の表）は、新しいステージのレベルを練習したことのある子に出す。アプリ情報に「あわせて89レベル・10ステージ（コースの版 2）」
* テスト用：診断をとばすレベルは、10ステージから選べる

## コンテンツを変えるときの手順

AGENTS.md に次の手順を書きます。

* レベルを足す：仕様にレベルを足し、`course.json` のステージの並び（または仕様のステージの `levelIds`）に入れ、`levelIdsEverUsed` に ID を足し、子ども向けの名前を足す。子どもの位置より前に入れば、更新のあとチェックで始める位置が決まる
* 並べ替える：`course.json` だけを直す。番号は自動で変わる。前提が前にあることはテストが確かめる。子どもの位置より前へ動いた、まだ練習していないレベルは、更新のあとチェックで始める位置が決まる
* 名前（ID）を変える：新しい ID のレベルにし、`renamedLevels` に「前の ID → 新しい ID」を足し、`levelIdsEverUsed` に新しい ID を足す
* 外す：仕様から消し、`retiredLevels` に足す。記録は消えずに残り（画面と予定は読み飛ばす）、ごほうびも減らない
* ステージを足す・外す：新しい数の ID を使う（使い回さない）。外すときは `retiredStages` に足す
* 形を変える（保存する項目を変える）：persist の version を上げ、`src/state/migrate.ts` に1つ前の版からの移行を足し、テストを書く
* `course.json` を変えたら `version` を1つ上げる

## テスト

* コース：`validateCourse()` が空、番号、文の置きかえ、子ども向けの名前
* 進み方と予定：ステージ0〜5だけのコースで、ドメインと同じ結果（ランダムな記録）。チェック待ちがある日の予定、frontier がチェック待ちを飛ばすこと
* チェック：合格、つまずき（ミスあり、遅いだけ、練習ずみ）、途中でやめたとき、1日1ステージ、ごほうびの基準
* 診断：ステージ0〜5だけのコースでドメインと同じ結果。10ステージを通る診断
* 合わせ込み：前の作業の記録（`6-1` などの ID、開いた単元）、レベルを足したとき（前とうしろ）、前へ動いたレベル、付け替え（前の ID と今の ID の両方に進み具合があるときを含む）、外したとき（ごほうびが減らない、画面のデータがこわれない）、新しい版のアプリが書いた記録を読んでも何も消えないこと、診断の途中、何回通しても同じ
* 移行：version 2 の記録（前の作業の記録を含む）を読み込んで、version 3 の形になり、合わせ込みがかかる
