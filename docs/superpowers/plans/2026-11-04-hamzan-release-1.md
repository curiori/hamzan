## ゴール

記録の書き出しと読み込み、本番と開発のビルドの設定、iPad の設定を作り、Apple Developer Program と EAS の手続きが済めば、すぐに本番版を家族の端末へ配れるようにする。

## 作り

`app.config.ts` が `app.json` を読み、`APP_VARIANT`（`eas.json` のプロファイルが渡す）でビルドの種類を決める。本番はテスト用の機能なし、開発は別のアプリ ID、どちらでもないとき（Expo Go、web、手元の書き出し）は今と同じ。記録のファイルは純粋なモジュール `src/state/backup.ts` が作って読み、古い保存の形は今の移行と合わせ込みを通す。ストアの `replaceRecords` が、読み込んだ記録で端末の記録を置き換える。ファイルの受け渡し（共有シート、ファイルを選ぶ画面、web のダウンロード）は `src/platform/records-file.ts` だけが端末にふれる。

## 使うもの

Expo SDK 58、expo-file-system（`File`、`Paths`）、expo-sharing（`shareAsync`）、expo-document-picker（`getDocumentAsync`）、EAS Build（`eas.json`）、zustand 5、bun test。

## 設計

`docs/superpowers/specs/2026-11-03-hamzan-release-design.md` の「① 家族の端末に本番版を入れる」。この計画は、そのうち Apple Developer Program と Expo のアカウントがなくてもできる作業を扱う。EAS へのつなぎこみ、端末の登録、ビルド、内部配布は、持ち主の手続きのあとに README の手順で行う。

## 全体の決まり

* `src/domain` と `curriculum.json` は変えない。`bun run test:domain` は通ったまま
* テストが読むモジュールは react-native と Expo を import しない
* Expo Go で今までどおり動く。Expo Go に入っていないネイティブモジュールと、prebuild が要る設定プラグインは入れない。expo-dev-client は②まで入れない
* 保存の形（persist の version 3、キー `hamzan-ios-v1`）は変えない
* 本番ビルド（`APP_VARIANT=production`）にテスト用の機能を出さない
* テスト用の設定（`dev`）は書き出さない。読み込んだあとは既定値にする
* 端末の記録を置き換えるのは、保護者が確かめの窓で「読み込む」を選んだときだけ
* 保護者向けの文は今の保護者の画面と同じ漢字かな交じり。子ども向けの文は変えない
* 各タスクの終わりに `bun run typecheck`、`bun run lint`、`bun test` を通してコミットする（Conventional Commits、絵文字と `- Generated by Copilot`、Co-authored-by）

## Review Focus

* Expo Go で書き出したファイルを、まだ何もない本番版の最初の画面で読み込む。PIN の設定や子どもの登録をやり直さず、ファイルの PIN で、その子の続きから始まること（Task 3 のテスト）
* 端末の記録が読めなかったとき（`loadError`）にファイルを読み込む。ファイルの記録が保存され、そのあとの練習も保存されること（Task 3 のテスト）
* 途中で切れたファイル、手で書きかえたファイル、ほかのアプリのファイル、写真を選ぶ。わけを伝え、端末の記録は何も変わらないこと（Task 2 のテスト）
* 新しい版のアプリが書き出したファイルを読む。断って、アプリを新しくするように伝えること（Task 2 のテスト）
* テスト用の設定をオンにした Expo Go のファイルを本番版で読む。テスト用の欄も設定も持ちこまれないこと（Task 1、Task 2、Task 3 のテスト）

### Task 2: 記録のファイル

ファイル

* 作る：`src/state/backup.ts`
* 変更：`src/state/migrate.ts`（`SAVE_VERSION`）、`src/state/create-store.ts`（`version: SAVE_VERSION`）
* テスト：`tests/state/backup.test.ts`

インタフェース

* `migrate.ts`：`export const SAVE_VERSION = 3`
* `backup.ts`
  * `interface Records { pin: PinRecord | null; profiles: Profile[]; activeId: string | null }`
  * `interface BackupFile { app: "hamzan"; version: number; exportedAt: string; state: Records }`（`exportedAt` は ISO 8601）
  * `backupText(r: Records, now: number): string`：`dev` を入れない
  * `backupFileName(now: number, device: string): string`：端末の時刻で `hamzan-YYYYMMDD-HHmm-<device>.json`
  * `type BackupError = "notRecords" | "tooNew" | "broken" | "empty"`
  * `type BackupRead = { ok: true; records: Records; exportedAt: string } | { ok: false; reason: BackupError }`
  * `readBackup(text: string): BackupRead`

読む順番（`readBackup`）

1. JSON でない、オブジェクトでない、`app` が `"hamzan"` でない：`notRecords`
2. `version` が 1 以上の整数でない：`broken`。`SAVE_VERSION` より大きい：`tooNew`
3. `exportedAt` が文字列でない、`state` に `profiles` の配列がない：`broken`
4. `SAVE_VERSION` より古ければ `migrate(state, version)` を通す。PIN は `null` か `hash` と `salt` の文字列。どのプロフィールも version 3 の入れ物（`progress`、`reviews`、`sets`、`facts`、`errors`、`stageChecks`、`sessions`、`settings`、`challenge`、`wallet`、`inventory`、`room`、`ledger`、`course` の `seen` と `checks`）を正しい型で持ち、ID が重ならない。合わないか、移行が例外を投げたら `broken`
5. プロフィールが 0 人：`empty`
6. どのプロフィールにも `reconcileProfile` を通す。`activeId` がいない子をさすときは最初の子にする

手順

- [ ] `tests/state/backup.test.ts` を書く
  * 「a file round-trips every child, the PIN and the active child, and leaves the test settings out」：ひらがなの名前の2人と PIN、2人目が選ばれている記録を `backupText` から `readBackup` に通すと、同じ記録が戻る。テキストに `"dev"` がなく、`app` が `hamzan`、`version` が 3、`exportedAt` が `new Date(now).toISOString()`
  * 「text that is not a records file is refused as not records」：`""`、`"こんにちは"`、`"[]"`、`"{}"`、`{"app":"other"}`
  * 「a file from a newer app is refused」：`version: 4` で `tooNew`
  * 「a damaged file is refused」：JSON の途中で切れたテキストは `notRecords`。`version` が `"3"`、`state` がない、`profiles` が配列でない、`sets` のないプロフィール、`hash` のない PIN、同じ ID の2人は `broken`
  * 「a file without children is refused as empty」
  * 「files of earlier save versions move forward like stored records」：version 2 の `6-1` に進み具合と `juku` のある子が、`frac-mixed` の進み具合と `course` を持つ。version 1 の子が `wallet` を持つ
  * 「an active child missing from the file becomes the first child」
  * 「file names carry the local date and time and the device」：`backupFileName(new Date(2026, 10, 4, 21, 5).getTime(), "ipad")` が `hamzan-20261104-2105-ipad.json`
- [ ] `bun test tests/state/backup.test.ts` で失敗を確かめる

* `records-transfer.ts`：`useRecordsTransfer(): { exportFile(): Promise<void>; importFile(): Promise<boolean>; busy: boolean; message: string | null }`。`importFile` は読み込んで置き換えたときだけ `true`

決まった文

* データの欄の見出し「記録の書き出しと読み込み」、説明「PIN と、すべてのお子さまの記録を1つのファイルに書き出します。AirDrop やファイル App で保存しておくと、別の端末や新しく入れたアプリで読み込めます。テスト用の設定は書き出しません。」、ボタン「記録を書き出す」「記録を読み込む」
* 最初の画面（`intro.tsx`）のボタン「書き出した記録を読み込む」（「PINを決める」の下、枠だけのボタン）
* 断るわけ：`notRecords`「ハムざんの記録のファイルではありません。」、`tooNew`「新しい版のハムざんで書き出した記録です。アプリを新しくしてから読み込んでください。」、`broken`「記録のファイルがこわれているため、読み込めません。」、`empty`「このファイルには、お子さまの記録がありません。」
* 確かめの窓：見出し「この記録を読み込みますか？」、ボタン「読み込む」。説明は「{書き出した日時} に書き出した記録です（さくら：セット記録 12件、たろう：セット記録 3件）。」に、端末に子がいれば「この端末の今の記録（はなこ）は消えて、ファイルの記録に置き換わります。元に戻せません。」を続け、最後に「PIN もファイルのものになります。」。端末に子がいるときだけ消すボタンの色にする
* うまくいかなかったとき：書き出し「書き出せませんでした。もう一度ためしてください。」、ファイルを開けない「ファイルを開けませんでした。」
* アプリ情報の「データの保存」：「この端末の中に保存します。保護者の画面の「データ」から、ファイルに書き出して別の端末へ移せます。外部への送信、広告、分析ツールはありません。」
