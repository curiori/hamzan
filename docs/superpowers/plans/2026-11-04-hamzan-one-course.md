## ゴール

89レベルを1本のコース（ステージ0〜9）にし、ID と画面の番号を分け、保存した記録を読むたびにコースへ合わせ込んで、配布後にレベルを足す・並べ替える・付け替える・外しても記録が失われないようにする。

## 作り

コースの形は `src/course/course.json` が正、レベルとステージの中身は `curriculum.json` と `juku.json` が正。`src/course` が両方を1本の並び（`COURSE`）にし、進み方、チェック、きょうの予定、診断を、ドメインと同じ決まりでその並びの上に組み直す。`src/state/reconcile.ts` が読み込みのたびに記録をコースへ合わせ込み、`src/state/migrate.ts` が version 2 の記録を 3 へ移す。

## 使うもの

TypeScript 6、Expo SDK 58、zustand 5（persist の `migrate` と `merge`）、bun test。

## 設計

`docs/superpowers/specs/2026-11-04-hamzan-one-course-design.md`

## 全体の決まり

* `src/domain` と `curriculum.json` は変えない。`bun run test:domain` は通ったまま
* テストが読むモジュールは react-native と Expo を import しない
* 画面の番号は `levelLabel(id)` と `stageNo(id)` からだけつくる。ID を分解して番号にしない
* 記録を消さない。知らない ID は残して読み飛ばす
* 子ども向けの文言はひらがな中心
* 各タスクの終わりに `bun run typecheck`、`bun run lint`、`bun test` を通してコミットする（Conventional Commits、絵文字と `- Generated by Copilot`、Co-authored-by）

## Review Focus

* 更新の日に、きょうの予定がすでに保存されている（前の作業の `juku` の区切り、ステージ ID だけのステージチェック）。ホームとセッションが止まらず、区切りが進むこと（Task 6 のテスト）
* 受験の技（ID 5）の途中の子が更新を入れる。新しい3ステージ（22レベル）がチェック待ちになり、1日1ステージずつチェックが進むこと（Task 6 のストアのテスト）
* チェックのセットを途中でやめる。何も変わらず、区切りも終わらないこと（Task 6）
* 新しい版のアプリが書いた記録（知らないレベルの進み具合、復習、ミス、予定）を読む。止まらず、何も消えないこと（Task 5 と Task 6）
* 診断の途中で更新を入れる。前に入った新しいステージのチェックに戻ること（Task 5）
